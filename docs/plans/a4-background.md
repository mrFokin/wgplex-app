# A4 — фон

Статус: план, ждёт согласования. Ветка `a4-background` от `master`.

**Цель:** автозапуск (design 6), уведомления (7), проверка обновлений (2), окно настроек (5, ⌘,).

## Решения

1. **Логика в `WgplexKit` (XCTest, без сети и AppKit):**
   - `NotificationPlanner` — чистая функция `(prev: EngineState?, next: EngineState, now, state) -> [AppNotification]` с небольшим состоянием (время последнего уведомления по туннелю, уже показанная версия). Таблица design 7: туннель умер и правила ушли на резерв/fallback при `reason: dead` → «X не отвечает: правила → Y»; восстановление; ошибка конфига (`config_error_count` вырос — «при reload», если предыдущий опрос был `ready`; при старте демона — «запущен без туннелей»); демон пропал/вернулся; новая версия. События одного опроса сливаются в одно уведомление; «мигание» одного туннеля — не чаще раза в 5 минут. Пауза, переключения, `reason: disabled|paused` — молчим. Первый опрос после запуска приложения только запоминает состояние (старый ⚠ не уведомляет). Каждое уведомление несёт раздел окна для клика.
   - `UpdateCheck` — разбор ответа `GET https://api.github.com/repos/mrFokin/wgplex-app/releases/latest` (`tag_name`, `html_url`), сравнение версий с `appVersion`, решение «пора ли проверять» (раз в сутки, по замыканию-часам), версия, о которой уже уведомили. Сеть — через замыкание-источник `Data`; сбой сети/404 (репозитория ещё нет) — молча, без баннера.
   - `WindowModel`: баннер «Доступна новая версия» (после «правило на резерве», ниже всех проблем) с командой `brew upgrade --cask wgplex-app` (копирование) и ссылкой на релиз — по решению A3 п.1.
2. **Приложение (`Sources/Wgplex`):**
   - `Settings` на `UserDefaults`: «Проверять обновления» (вкл.), «Уведомления» (вкл.); «Запускать при входе» — не в defaults, а по `SMAppService.mainApp.status`.
   - Окно настроек (⌘,): три переключателя + при `.requiresApproval` подсказка про «Объекты входа». Пункт «Настройки…» в главном меню.
   - `LoginItem`: `register`/`unregister` только по действию пользователя в окне или ответу на первый вопрос; ошибки — текстом в окне.
   - Первый запуск (флаг в defaults): один `NSAlert` «Запускать Wgplex при входе?» + запрос разрешения на уведомления.
   - `Notifier` на `UNUserNotificationCenter`; клик открывает окно на разделе уведомления (`WindowController`). Подключается к `StatusPoller.onState` (опрос уже раз в 10 с в фоне).
   - Проверка обновлений — таймер раз в сутки + при старте, если прошло >24 ч; результат кладётся в `WindowState` (баннер) и в `Notifier`.
3. **Бандл.** `UNUserNotificationCenter` и `SMAppService` требуют `.app` с `CFBundleIdentifier`; под `swift run` их нет (уведомления падают). В A4 без бандла обе функции отключаются (`Bundle.main.bundleIdentifier == nil` → переключатели неактивны с подписью «нужна сборка .app»), приложение не падает. `Info.plist`, `LSUIElement`, `make dmg` — A5. Для проверки в VM — скрипт `scripts/vm-check/make-app.sh` (одноразовый ad-hoc бандл из `.build`), не часть поставки.
4. **Не в A4:** `Info.plist` для релиза, `make dmg`, README, релиз, cask (A5); Sparkle не используется; авто-обновление — нет, только подсказка команды.

## Правки design.md в этой ветке

Только если выяснится расхождение. Заранее: в разделе 7 уточнить, что при первом опросе после запуска приложения уведомления не шлются (это решение п.1).
