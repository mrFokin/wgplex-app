# wgplex-app — документ проектирования

Разделы 2–8 перенесены из раздела 17 `docs/design.md` репозитория `wgplex` (шаг A0); раздел 9 — из 21.2 и 21.3 того же документа. Дальше правки вносятся здесь.

## 1. Задача и связь с движком

Wgplex.app — меню-приложение macOS, клиент публичного API движка `wgplex` (отдельный репозиторий `mrFokin/wgplex`; демон и CLI в одном бинарнике). Приложение не управляет системой само: всё через JSON-RPC 2.0 по unix-сокету `<prefix>/var/run/wgplex.sock`. В нём нет привилегированного кода и нет чтения конфига движка.

- «design wgplex N» — раздел N `docs/design.md` репозитория `wgplex`. Там же: модель угроз и права (5), API (14), логи (15), сборка и поставка движка (16).
- Контракт API — `docs/api.md` движка; он появится в M3. До тех пор поля и ошибки, которых в API движка ещё нет (`reason` у правил, `can_control`, `api_version`, `paused`, ошибка `5`, `tunnel.enable`/`disable`, `daemon.pause`/`resume`), в разделах 3–7 — намерение, а не контракт.
- «M0, K4», «M0, S1» и т. п. — факты spike движка, см. `docs/plans/m0-spike.md` репозитория `wgplex`.

## 2. Поставка

- **Основной канал — cask `wgplex-app`** в `mrFokin/homebrew-tap`: `depends_on formula: "mrfokin/tap/wgplex"`, `depends_on macos: ">= :ventura"`, `.dmg` из релиза GitHub. Запасной — тот же `.dmg` вручную (universal, ad-hoc подпись).
- Установка: `brew trust mrfokin/tap`, затем `brew install --cask mrfokin/tap/wgplex-app`. Homebrew 7 доверяет по полному имени только самому cask, а формулу-зависимость из того же tap без `brew trust` не загружает (M0, K4, K11).
- Developer ID пока нет. Первый запуск (M0, K6, K7): диалог «"Wgplex" Not Opened — Apple could not verify…», кнопка «Done» (не «Move to Trash»); затем «Системные настройки → Конфиденциальность и безопасность» → «"Wgplex" was blocked to protect your Mac» → «Open Anyway» → пароль администратора. Тексты — в README. С подписью меняется только этап сборки.
- **Обновление через `brew upgrade --cask` повторного разрешения не требует:** Homebrew сохраняет каталог `.app` и переносит одобрение (M0, K8, K9). Ручная замена из `.dmg` — требует «Open Anyway» снова (M0, K10).
- Обновления: раз в сутки запрос последнего релиза через GitHub API (если включено «Проверять обновления»). Новая версия — одно уведомление на версию (7) и баннер в окне до обновления: команда `brew upgrade --cask wgplex-app` с копированием и ссылка на страницу релиза. Sparkle не используется.

## 3. Движок

- Сокет ищется по `/opt/homebrew/var/run/wgplex.sock`, затем `/usr/local/var/run/wgplex.sock`; переопределение — в настройках.
- Установлен ли движок — по `<prefix>/opt/wgplex/bin/wgplex`, работает ли — по сокету: при остановке службы демон удаляет файл сокета, и «сокета нет» не значит «не установлен».
- Три состояния без движка: бинарника нет — «wgplex не установлен», «Как установить…»; бинарник есть, сокета нет или он не отвечает — «Демон не запущен», команда `sudo brew services start --sudo-service-user=root wgplex` с копированием; `api_version` меньше нужной — «Обновите wgplex»: `brew upgrade wgplex` и `sudo brew services restart --sudo-service-user=root wgplex`.
- «Выход» закрывает только приложение: туннели принадлежат машине. Остановка демона — `brew services`, не GUI.

## 4. Меню

`NSStatusItem` + `NSMenu` (AppKit): свежий `status.get` при открытии (`menuNeedsUpdate`), обновление раз в 1–2 с, пока меню открыто (таймер в `.common` mode); в фоне — раз в 10 с для иконки.

```
✓ nl
✓ de  ⚠
  work
──────────
⚠ youtube на резерве        (только когда есть проблема)
──────────
Приостановить               (на паузе — «Возобновить», галочки серые)
Открыть Wgplex…
Выход
```

- Галочка — туннель включён, щелчок переключает. ⚠ — включён, но мёртв или не поднялся.
- Строка проблемы (правило на резерве или в fallback, ошибка конфига, демон недоступен) открывает окно на нужном месте.
- Без права управления (`can_control: false`) туннели и «Приостановить» неактивны.
- Иконка — template: контурный щит (всё выключено), залитый (работает), с «!» (проблема), с паузой.

## 5. Окно

Боковая панель и содержимое раздела (SwiftUI). Приложение без значка в Dock (`LSUIElement`); значок появляется, пока окно открыто.

- **Панель действий** во всех разделах: Приостановить/Возобновить, Выключить все, Перечитать конфиг. Без права управления — неактивны.
- **Баннер** сверху: ошибка конфига, демон недоступен, пауза, правило на резерве, доступна новая версия.
- **Туннели:** список с переключателями; детали выбранного — endpoint, интерфейс и адрес, handshake, трафик, маршрутов, проверка.
- **Правила:** сервисы, `via`, текущий туннель, состояние.
- **Диагностика:** поле `explain`, таблица маршрутов.
- **Логи:** хвост файла из `log_path`, поиск, фильтр по уровню, дочитывание, пока раздел открыт. Без членства в `control_group` файл недоступен (design wgplex 15) — «нужно членство в группе …».
- **Открыть папку конфига** — если `config_dir` доступен текущему пользователю на чтение (на практике владелец); иначе — путь и «Конфиг правит администратор».
- **Настройки** (⌘,): запуск при входе, уведомления, путь к сокету, проверка обновлений.

## 6. Автозапуск

- `SMAppService.mainApp` (видно в «Объектах входа» → «Open at Login» одной записью под своим именем). С ad-hoc подписью регистрация — сразу `enabled`, без одобрения; система один раз показывает уведомление. Регистрация переживает обновление бандла с другим cdhash и перезагрузку — запись та же (M0, S1–S5). После `unregister` запись остаётся выключенной, повторная регистрация уведомления не даёт (M0, S6).
- По умолчанию выключен. При первом запуске — один вопрос «Запускать Wgplex при входе?» и запрос разрешения на уведомления.
- Каждый пользователь включает сам. Для всех пользователей сразу — команда для админа в README (plist в `/Library/LaunchAgents`), без привилегированного кода в приложении.

## 7. Уведомления

Приложение сравнивает соседние ответы `status.get` (раз в 10 с); движок не меняется. Работают, пока приложение запущено.

| Событие | Пример |
|---|---|
| Туннель включён, но умер или не поднялся, и правила ушли на резерв или в fallback | «nl не отвечает: youtube, ai → de» |
| Восстановление | «nl снова работает, youtube через nl» |
| Ошибка конфига при `reload` | «Изменения конфига не применены: 2 ошибки. Работает прежний конфиг» |
| Ошибка конфига при старте | «wgplex запущен без туннелей: конфиг с ошибками» |
| Демон пропал / вернулся | «wgplex не работает» |
| Новая версия приложения (2) | «Доступна Wgplex 1.3» — один раз на версию |

- Не уведомляет о намеренных действиях — в том числе сделанных другим пользователем или из CLI: о резерве и fallback уведомляет только при `reason: dead` (design wgplex 14), паузу и переключения не замечает. Не уведомляет о результате собственного «Перечитать» — он виден в окне.
- События одного опроса — одно уведомление; о «мигающем» туннеле — не чаще раза в 5 минут.
- Одна галочка в настройках, по умолчанию включена. Щелчок открывает окно на нужном разделе.

## 8. Сборка

Swift Package, macOS 13+, без сторонних зависимостей. `make dmg` — `swift build -c release --arch arm64 --arch x86_64`, бандл, ad-hoc подпись с постоянным требованием `codesign --sign - -r='designated => identifier "io.github.mrfokin.wgplex"'` (иначе требование — cdhash, и при `brew upgrade --cask` Homebrew пишет «signer changed» и не переносит одобрение, M0, K8, K9), `hdiutil create`; релиз — `gh release create` с `.dmg` (design wgplex 16.1). Код — копия `app/` Wirefork (клиент RPC, модели статуса) без чтения и отправки конфига; меню переписывается на AppKit. Логика (клиент, представление статуса, вычисление уведомлений) — в библиотечном таргете `WgplexKit` под XCTest, с фейковым сервером API.
